# Contributing

Keep the game small, readable, and compatible with both the original CHGame console and the maintained WeAct port. Changes should fit the measured flash and SRAM budgets and preserve the handheld's button-only controls.

## Development loop

1. Follow the setup instructions in [README.md](README.md).
2. Change rules in `Game.cpp`, presentation in `View.cpp`, or original artwork in `tools/assets.py` and `tools/cart.py` inside the game folder. Regenerate assets from their recipes rather than hand-editing generated byte arrays.
3. Run `python tools/project.py build` and `python tools/project.py check`. Add a meaningful regression for a changed rule, save contract, or exit behavior.
4. If pixels change, run `python tools/project.py gifs` and inspect the recordings at native size. Keep the gameplay GIF and each tutorial below 1 MB. Label debug fixtures accurately.
5. Review the flash/save and SRAM budgets in the build report before distributing new firmware. Run `python games/EmberHollow/tools/package_boards.py` after building all four profiles, then `--check` to verify the committed board packages. Regenerate the root `SHA256SUMS.json` entries for every changed or added tracked file, using SHA-256 of the exact file bytes; the manifest excludes itself. Never relabel one board's image as the other.

The game logic uses fixed-size pools, integer arithmetic, and no heap allocation. `gfx_wait()` must complete before saving flash or drawing into a buffer still being transferred. START must remain cancellable until five continuous seconds have elapsed, including on pause and ending screens.

## Saves and dependencies

The save identity is `EHLO`, version 1, with a 40-byte record. Preserve compatibility or explicitly increment the save version when the binary layout changes. Transient story and animation fields do not belong in that record.

Imported CHGame files are ignored dependencies. Do not patch them to implement a game feature. For a dependency update, change `dependency-lock.json` to an explicit reviewed commit, set up a fresh dependency, build release/debug for both targets, run checks, regenerate changed recordings, and verify CX35 and WF86 CHG headers, wrong-board rejection, and the combined cart. The game-local Rev0 adapter must be reviewed if the board definition, linker map, or build recipes change. Record what was actually tested.

## Pull requests

Explain the player-visible change, its reason, and the checks performed. Include before/after captures for visual changes and describe any save-format impact. Avoid personal details, credentials, device identifiers, and local account paths in issues or examples.

New contributions use the repository's Apache-2.0 license. Retain the existing third-party notices.
