# Ember Hollow: developer notes

Version 1.1.0 is a complete small quest for the original CHGame Rev0 console and the existing WeAct F8U6 variant. The game is original; Ethan's Critters supplies the broad exploration/combat inspiration. It deliberately uses a smaller tile world and flash-resident art to work with the current shared libraries without Critters' streaming patches.

## Design and memory

- World: 64x48 tiles of 8x8 pixels (512x384 pixels), generated by `tools/assets.py`. Wide bridges cross two lava rivers. Six shrines can be cleared in any order; their bitmask opens the northern gate.
- Fixed 30 Hz logic and rendering. Input, enemy timers, the clock, and effects advance in game ticks; pause stops the quest clock and victory freezes the completion time. The menu-exit hold uses elapsed `millis()` time independently of game ticks. This is a target rate, not a hardware measurement.
- Eight enemies, 16 particles, one boss; fixed arrays, no runtime allocation, no floating point. The standard CHGfx 8 KB framebuffer is the only full frame in RAM.
- Original 4-bit art: 20 sprites, 12 tiles, a 3 KB world table, and an 8 KB title image in flash. The public `gfx_blit` API draws them without a local graphics fork.
- The default display SPI clock is 12 MHz (`GFX_DIV4`) for breadboards. It is a game setting, not a change to the hardware variant. No SD transactions happen while playing.
- All save writes happen after `gfx_wait()` and before the next flush. A failed write is reported on the map and not retried every frame. A later checkpoint can try again.

Current memory figures for all four profiles are in the repository root's `BUILD_REPORT_BOARDS.md`; `BUILD_REPORT.md` records the earlier WeAct-only package. The flash limit with two save pages is 50,432 bytes; static SRAM budget is 18,416 bytes after the retained boot block and 2 KB stack. Measure again after changing art, code, libraries, or the toolchain.

## Save contract

Magic and debug handshake ID: **EHLO**. Configuration prefix: **EH_**. The identifier was checked against the current CHGame examples before adding this game.

`Progress` is a fixed 40-byte record on the RISC-V build: elapsed ticks, best ticks, checkpoint position, cleared-shrine mask, health, active/won flags, and 24 bytes of explored-map bits. It is zeroed when a new game starts. Increment `EH_SAVE_VERSION` when this layout changes.

The new `Intro` mode is appended as value 5, preserving existing mode values. Story page, ending timer, defeat cause, and new-best state are transient; the save remains 40 bytes with version 1. Opening NEW shows the story without clearing the previous save until the player completes or skips it.

Saving occurs on a shrine clear, pause/help, death, victory, and a completed menu-exit hold during play or pause. Continuing restores that checkpoint. Partial shrine damage, live enemies, boss damage, particles, and consumed candy are not saved. After death the checkpoint moves to the hut with full health; completed shrines and explored map areas remain. Starting NEW preserves only the best completion time.

## Story, endings, and menu exit

The three illustrated story pages explain the curse, introduce Wick, and give the six-shrine objective. A advances and B skips. Continuing bypasses the intro.

Defeat records the last damage source and presents a matching hint. Inputs unlock after 30 ticks: A retries at the hut, B returns to the title. Victory celebrates the restored lanterns; after 45 ticks A returns to the title and B explores with full hearts. The completion clock remains fixed after winning. Lava still hurts. The boss HUD displays current / maximum health and attack-phase cues throughout the live arena encounter.

`QuitHold.h` uses unsigned millisecond subtraction, including timer rollover. `chgame.startExits = false` disables the platform's shorter shortcut. After 500 ms, the view overlays a countdown; at 5,000 ms the sketch waits for display DMA, checkpoints where appropriate, saves, and calls `chgame.exitToMenu()`. Release resets the countdown. All modes share this path. The unchanged simulator prints its hardcoded “START held 3 s” message when the API is invoked; the regression test separately verifies that this game's invocation occurs only after five seconds.

## Regenerate assets

From the game folder, in a Python environment with Pillow and numpy:

```sh
python tools/assets.py
python tools/cart.py
```

Edit the recipes, then regenerate `src/assets/Assets.cpp`, `docs/title.png`, `docs/sprites.png`, `docs/world.png`, and `docs/cart.png`. Review at native size. `cart.py` uses CHGame's artkit and the visual menu's fixed-colour contract. The lettering is the game's own native stroke alphabet.

## Tests and simulator

Install the parent checkout's tools dependencies; a host C++ compiler is needed. From the CHGame repository root:

```sh
python tools/chgame.py --sketch games/EmberHollow check --no-device
python tools/readme_gif.py games/EmberHollow
```

On hosts where Arduino's `min`/`max` macros interfere with the compiler's standard-library headers, use the existing simulator workaround before the commands above:

```sh
export CHSIM_CXX=g++
export CHSIM_FLAGS="-include chrono"
```

`tools/tests/test_game.cpp` checks controls, collision, a traversable path to every shrine, the locked/open arena, combat direction, parries, healing, checkpoint validation, death persistence, boss warnings/victory, story transitions and skip, ending input gates, best-time handling, five-second timing/cancel/rollover, and 100,000 ticks of varied inputs. The current native run passed 503,252 assertions. It is also run with AddressSanitizer and UndefinedBehaviorSanitizer during package verification; leak detection is disabled because this execution environment prevents LeakSanitizer's process inspection.

`tools/tests/sim_save.py` exercises the sketch with CHGame's actual simulated flash pages. It checkpoints progress and health, simulates an application restart while retaining flash, continues, starts NEW through the story, cancels an early exit hold, remains running beyond three seconds, and exits successfully after five seconds. This checks the flash-record path, not physical power-loss behaviour.

`tools/scripts/smoke.txt` captures 15 states, including all story pages, full/half boss health, both endings, and quit/cancel. `gameplay.txt` records eight clips for the README GIF; `tutorials.txt` records five beginner clips. CHGame's checker runs all three scripts twice and compares every image. The game driver records at the configured 30 Hz, writes each GIF atomically, and decodes every frame before publishing it. Later preview clips use the documented debug fixtures to frame encounters; they do not claim to record a complete unassisted quest.

All game fixtures are absent from the release firmware:

| Debug command | Action |
|---|---|
| `Z` | Report mode, position, health, cleared mask, boss health/phase, elapsed ticks, story page, and quit milliseconds |
| `W x y facing` | Move to a walkable fixture position; facing 0 south, 1 west, 2 north, 3 east |
| `C mask` | Set the six shrine bits for a fixture (0-63) |
| `H hp` | Set fixture health (1-10) and brief invulnerability |
| `V` | Reset application and quit-hold state, then load the saved flash record |
| `J hp` | Set up a live Warden encounter with 1–24 health |
| `E` | Place a nearby warning skeleton for the parry demonstration |

To publish all recordings after a successful check, run from the repository root:

```sh
python tools/readme_gif.py games/EmberHollow --no-run
python games/EmberHollow/tools/tutorial_gifs.py
```

The standalone repository's `tools/project.py` bootstraps the locked dependency and offers `build`, `check`, and `gifs`. Its local-checkout import and root PlatformIO builds were verified on Linux. The WeAct release previously passed the complete GitHub workflow from a fresh checkout. CI now builds both boards and verifies their committed packages. Windows/macOS hosts and physical consoles have not been exercised here.

## Upstream maintenance

The WeAct environments extend the parent port's `env:game` and read its builder/core/libraries directly. `ember-rev0` and `ember-rev0-debug` use the small application-only adapter in `tools/platformio/rev0/`. This adapter reads `rev0.*` from the current dependency's `boards.txt`, compiles its `CHGame_Rev0` variant with `CH32X035G8U`, preserves the app/save memory map, and packages/uploads as `CX35`. It contains no copied Arduino core or game logic. Its build mechanics and pinned toolchain selection are adapted from the maintained WeAct PlatformIO port (Apache-2.0). Review this adapter when the dependency's build contract changes. It uses a unique absolute symlink alias to avoid PlatformIO resolving a platform from another checkout. The same sketch also builds from the parent root's game environment using `CHGAME_SKETCH`.

No shared CHGame files are modified. Rebuild `ember`, `ember-debug`, `ember-rev0`, and `ember-rev0-debug`, run `check --no-device`, regenerate the preview if pixels change, run `tools/package_boards.py --check`, and verify both board packages after each upstream merge. Never relabel a Rev0 binary as WF86. Rev0 and WeAct release/debug compilation are covered; hardware playtesting is still pending.

## Follow-up work

Check combat feel and TFT performance on the handheld, then tune the boss warning/recovery intervals if needed. Extra districts, enemies, quests, and sound can be added within the measured budgets. The current version has one fixed world and one final boss; it does not reproduce Critters' large streamed cutscenes or its purchased art.
